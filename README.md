# Internet Speed Test

Консольный инструмент на Python для измерения скорости скачивания данных с указанного HTTP/HTTPS-адреса.

## Что делает

1. Принимает URL загружаемого ресурса через аргумент командной строки.
2. Выполняет **10 последовательных HTTP GET-запросов по умолчанию** или выбранное число `--count` — следующий начинается только после полного чтения предыдущего ответа.
3. Измеряет время **каждого запроса от начала до полного чтения тела ответа** (`time.perf_counter`).
4. Считает среднее время запроса, общий объём полученных данных и среднюю скорость скачивания.
5. Показывает результаты в терминале. Данные читаются блоками по 64 КиБ, без сохранения на диск.

**Требования:** Python 3.10 или новее. Во время работы используется только стандартная библиотека. Для сборки и установки нужны pip и setuptools>=70.1; pip подготавливает backend сборки автоматически.

## Запуск

Склонируйте репозиторий:

```bash
git clone https://github.com/Kordava/internet-speed-test.git
cd internet-speed-test
```

Установите команду в изолированное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
internet-speed-test --help
internet-speed-test "https://example.com/path/to/large-file.bin" --count 3 --json
```

В Windows активируйте окружение командой `.venv\Scripts\activate` (cmd) или
`.venv\Scripts\Activate.ps1` (PowerShell). Установленная команда работает из любого
каталога и поддерживает все описанные ниже параметры.

Прямой запуск из исходников также доступен без установки:

Запустите тест, указав URL **реально существующего** большого файла, доступного без авторизации:

```bash
python3 speed_test.py "https://example.com/path/to/large-file.bin"
```

> **Важно:** адрес `example.com/path/to/large-file.bin` — только шаблон. Замените его реальным адресом файла. Для содержательного замера лучше выбрать файл размером несколько мегабайт или больше.

`--timeout` задаёт таймаут **блокирующих сетевых операций** (по умолчанию 30 секунд). Он не ограничивает DNS или общую длительность скачивания.

`--download-timeout` задаёт **общую отсечку каждой попытки** (по умолчанию 120 секунд): запуск рабочего процесса, DNS, соединение, TLS, редиректы, заголовки и тело. Непрерывная медленная передача также останавливается по этой отсечке:

```bash
python3 speed_test.py "https://example.com/path/to/large-file.bin" --timeout 60 --download-timeout 180
```

В Windows можно использовать `python` вместо `python3`.

### Число запросов и бюджет серии

`--count N` задаёт положительное целое число запросов (по умолчанию 10).
`--max-time SECONDS` ограничивает общую длительность серии положительным конечным числом секунд.
`--max-bytes BYTES` ограничивает суммарные байты тел ответов положительным целым числом без суффиксов.
Общие лимиты по умолчанию отключены; их можно использовать вместе:

```bash
python3 speed_test.py "https://example.com/path/to/large-file.bin" --count 3 --max-time 20 --max-bytes 10000000
```

Общий срок начинается перед первым worker и учитывает запуск процессов, DNS, соединения, TLS,
редиректы, чтение, промежутки между запросами, вывод прогресса и уборку предыдущих попыток.
Из общего срока и `--download-timeout` действует более ранний; при равенстве — общий.
Отсечка останавливает текущую загрузку, включая медленное или бесконечное тело.
Уборка после отсечки требует дополнительного времени. Уже принятый до срока последний полный
ответ остаётся успешным после подтверждённой уборки. Вывод предполагает работающие stdout/stderr:
зависший потребитель консоли может задержать выход программы.

Байтовый лимит относится к данным конечных HTTP-тел после удаления chunk framing, без
декодирования Content-Encoding. Тела редиректов, framing и буферы ОС/TLS в него не входят;
это **не ограничение сетевого трафика**. Worker никогда не запрашивает у reader больше остатка
бюджета. При исчерпании лимита дополнительный байт ради проверки EOF не читается.
Полное тело с Content-Length ровно на границе считается успешным. Для chunked и EOF ровно
на границе ответ остаётся неполным: подтверждение нулевого chunk/trailers/EOF требует ещё одного
чтения. Для таких ответов задайте бюджет больше тела, если требуется подтвердить завершение.
При исчерпании бюджета между запросами следующая попытка не запускается, даже если могла бы быть пустой.

Остановка по общему времени даёт `time_limit`, по байтам — `byte_limit`; код выхода `1`.
Между запросами сначала проверяется время, затем байты. Во время запроса terminal error/limit,
полученный до срока, сохраняет причину; поздний результат не отменяет отсечку времени.
Завершённые запросы и известные данные текущей попытки сохраняются. При остановке между
попытками строка `Partial request` отсутствует. Для незавершённой серии статистика и скорость
относятся только к полным ответам и явно подписаны `Completed requests only` / `Completed-only speed`.

## Текстовый и JSON-отчёт

Прогресс `Request 01/10: ...`, предупреждения и диагностика идут в `stderr`.
Итоговый отчёт идёт в `stdout`. Пример текста для `--count 2` (числа иллюстративные):

```text
URL: https://example.com/path/to/large-file.bin

Results
Completed: 2/2 requests
Download 01: 2.000 s, 1,000,000 bytes
Download 02: 6.000 s, 3,000,000 bytes
Average request time: 4.000 s
Min request time:     2.000 s
Median request time:  4.000 s
Max request time:     6.000 s
Total downloaded:     4,000,000 bytes (3.81 MiB)
Total request time:   8.000 s
Download speed:       4.00 Mbit/s
```

`--json` выводит ровно один JSON-документ с завершающим переводом строки:

```bash
python3 speed_test.py "https://example.com/path/to/large-file.bin" --count 2 --json > result.json
```

Пример того же результата (для удобства отформатирован):

```json
{
  "schema_version": 1,
  "url": "https://example.com/path/to/large-file.bin",
  "status": "completed",
  "requested_count": 2,
  "completed_count": 2,
  "downloads": [
    {"number": 1, "elapsed_seconds": 2.0, "bytes_downloaded": 1000000},
    {"number": 2, "elapsed_seconds": 6.0, "bytes_downloaded": 3000000}
  ],
  "statistics": {
    "total_bytes": 4000000, "total_seconds": 8.0, "average_seconds": 4.0,
    "min_seconds": 2.0, "median_seconds": 4.0, "max_seconds": 6.0, "speed_mbps": 4.0
  },
  "partial": null,
  "error": null,
  "warnings": []
}
```

Все поля присутствуют и при остановке: `status="incomplete"`, `error={"reason": ..., "detail": ...}`.
В тексте вместо `Results` выводится `Series incomplete` с причиной. `downloads` содержит только
полные ответы; `statistics` относится только к ним. При нуле полных ответов суммы равны нулю,
остальные статистики — `null` (в тексте `N/A`). При чётном количестве медиана — среднее двух
центральных времён. Числа JSON не округляются для отображения; NaN/Infinity запрещены.

`partial` — `null` при остановке между запросами либо объект
`{"number": 3, "bytes_downloaded": 123, "elapsed_seconds": 0.5, "exact_bytes": false}`.
Начатая попытка с нулём байтов также сохраняется. `exact_bytes=false` означает нижнюю границу,
в тексте `at least`; частичная попытка не входит в суммы, времена и скорость полных ответов.
Даже отмена после последнего полного ответа остаётся незавершённой серией.

Первая полученная порция сразу передаётся родительскому процессу. Последующий прогресс
передаётся при накоплении ещё 1 МиБ или через 100 мс, с проверкой после очередного чтения.
Во время заблокированного чтения обновлений нет: при принудительной остановке нижняя граница
может отставать от фактически прочитанного объёма. Полный результат и ошибки, переданные
рабочим процессом, сохраняют точный счётчик независимо от частоты обновлений прогресса.

Если среднее время полного запроса **меньше 1 секунды**, `warnings` содержит
`"short_measurement"`, а `stderr` — одно предупреждение: такой замер сильнее зависит от задержек
и не гарантирует оценку пропускной способности. При среднем времени от 1 секунды и без полных
ответов предупреждения нет. Правило действует и для завершённого префикса неполной серии,
не меняя код выхода. Лучше использовать достаточно большой файл.

## Единицы и формула

- **Время запроса:** секунды (`s`).
- **Общий объём:** байты (`bytes`), дополнительно мебибайты (`MiB = 1 048 576 bytes`).
- **Скорость:** мегабиты в секунду (`Mbit/s`, где `1 Mbit = 1 000 000 bits`).

Формула скорости (по завершённым полным скачиваниям):

```text
speed_mbit_s = total_bytes * 8 / sum(request_times_seconds) / 1_000_000
```

В расчёт времени включены DNS, установление соединения, TLS, редиректы, ожидание ответа и полное чтение конечного тела. Запуск и завершение рабочего процесса, паузы между запросами и вывод в консоль в знаменатель не входят. Измеряются байты HTTP-тела после удаления chunk framing, без декодирования Content-Encoding.

## Тесты

Тесты используют локальные HTTP/HTTPS-серверы и **не требуют интернета**. TLS проверяется с тестовым CA из `tests/fixtures`; ключ сервера предназначен только для этих тестов:

```bash
python3 -m unittest -v tests.test_speed_test
```

Проверки установки дополнительно требуют pip>=22.3 и setuptools>=70.1 в окружении,
из которого запускаются тесты. Подготовьте средства сборки заранее (этот шаг требует сети):

```bash
python -m pip install "pip>=22.3" "setuptools>=70.1"
python -m unittest discover -s tests -t . -v
```

Полный набор собирает wheel из временной копии исходников и устанавливает его в чистый
временный venv без сети, проверяет состав пакета и повторяет CLI-проверки установленной
командой вне checkout. При отсутствии средств сборки проверки установки завершаются
явной ошибкой. Временные файлы создаются в системном temp; его можно выбрать через `TMPDIR`.

Проверяются полные и пустые ответы с Content-Length, chunked и EOF, пользовательское число запросов, общие лимиты и их взаимодействие, точные байтовые границы, обрывы и повреждённый framing, редиректы, ошибки TLS/HTTP/DNS/соединения, оба таймаута, текстовый и JSON-отчёты, статистика и предупреждения, сохранение частичного результата, завершение worker и корректность формул. Проверки сигналов группы процессов и повреждённого IPC выполняются на POSIX; проверка отсутствия оставшихся CLI-процессов использует Linux `/proc`.

## Обработка ошибок и ограничения

- Код `0` означает, что все запрошенные ответы прочитаны полностью. `Results` печатается только в этом случае; JSON получает `status="completed"`.
- При ошибке сети, HTTP, framing или таймауте серия останавливается с кодом `1`, при Ctrl+C — с кодом `130`. Ожидаемые ошибки выводятся без traceback.
- В `stderr` сохраняются число, байты и суммарное время завершённых запросов, отдельно — номер, известные байты, время и причина остановки текущей попытки. При принудительной остановке `at least N bytes` означает нижнюю границу: последний полученный progress; ещё не переданные счётчики и буферы ОС/TLS в неё не входят.
- Причины остановки: `http_error`, `network_error`, `io_timeout`, `download_timeout`, `time_limit`, `byte_limit`, `incomplete_response`, `protocol_error`, `cancelled`, `worker_error`.
- Content-Length должен быть неотрицательным и согласованным во всех повторениях. Chunked требует полного framing, нулевого chunk и завершённых trailers. Повреждённые и неоднозначные длины отклоняются. Для ответа без длины и Transfer-Encoding EOF считается полным ответом; неизвестную недостачу обнаружить невозможно. 204 — успешный пустой ответ.
- Поддерживаются до десяти редиректов 301/302/303/307/308 только на HTTP(S). Промежуточные тела не скачиваются и не учитываются в объёме; время переходов учитывается. Повторных попыток при ошибке нет.
- Стандартная проверка HTTPS-сертификатов и proxy environment сохраняются.
- Каждую попытку выполняет отдельный процесс со `spawn`; следующая начинается только после его завершения и уборки. После отсечки остановка может занять ещё до 0,5 с на каждое из ожиданий terminate/join, kill/join и receiver join. Это не гарантия реального времени ОС. Неподтверждённая уборка даёт `worker_error` и прекращает серию.
- Недопустимый URL, таймаут, число запросов или лимит отклоняется до начала работы (`argparse`, код `2`).
- Измерение отражает пропускную способность **до конкретного сервера по HTTP**, а не гарантированную максимальную скорость интернет-тарифа. На результат влияют сервер, сетевые задержки, TLS и размер файла.
