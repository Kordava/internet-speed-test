# Internet Speed Test

Консольный инструмент на Python для измерения скорости скачивания данных с указанного HTTP/HTTPS-адреса.

## Что делает

1. Принимает URL загружаемого ресурса через аргумент командной строки.
2. Выполняет **ровно 10 последовательных HTTP GET-запросов** — следующий начинается только после полного чтения предыдущего ответа.
3. Измеряет время **каждого запроса от начала до полного чтения тела ответа** (`time.perf_counter`).
4. Считает среднее время запроса, общий объём полученных данных и среднюю скорость скачивания.
5. Показывает результаты в терминале. Данные читаются блоками по 64 КиБ, без сохранения на диск.

**Требования:** Python 3.10 или новее. Сторонние пакеты не нужны (используется стандартная библиотека).

## Запуск

Склонируйте репозиторий:

```bash
git clone https://github.com/Kordava/internet-speed-test.git
cd internet-speed-test
```

Запустите тест, указав URL **реально существующего** большого файла, доступного без авторизации:

```bash
python3 speed_test.py "https://example.com/path/to/large-file.bin"
```

> **Важно:** адрес `example.com/path/to/large-file.bin` — только шаблон. Замените его реальным адресом файла. Для содержательного замера лучше выбрать файл размером несколько мегабайт или больше.

`--timeout` задаёт таймаут **блокирующих сетевых операций** (по умолчанию 30 секунд). Он не ограничивает DNS или общую длительность скачивания.

`--download-timeout` задаёт **общую отсечку каждой попытки** (по умолчанию 120 секунд): запуск рабочего процесса, DNS, соединение, TLS, редиректы, заголовки и тело. Непрерывная медленная передача также останавливается по этой отсечке:

```bash
python3 speed_test.py "https://example.com/path/to/large-file.bin" --timeout 60 --download-timeout 180
```

В Windows можно использовать `python` вместо `python3`.

## Пример вывода

Числа ниже иллюстративные:

```text
URL: https://example.com/path/to/large-file.bin

Request 01/10: 0.833 s, 10,000,000 bytes
Request 02/10: 0.815 s, 10,000,000 bytes
...
Request 10/10: 0.820 s, 10,000,000 bytes

Results
Average request time: 0.823 s
Total downloaded:     100,000,000 bytes (95.37 MiB)
Total request time:   8.230 s
Download speed:       97.21 Mbit/s
```

## Единицы и формула

- **Время запроса:** секунды (`s`).
- **Общий объём:** байты (`bytes`), дополнительно мебибайты (`MiB = 1 048 576 bytes`).
- **Скорость:** мегабиты в секунду (`Mbit/s`, где `1 Mbit = 1 000 000 bits`).

Формула скорости (по всем десяти скачиваниям):

```text
speed_mbit_s = total_bytes * 8 / sum(request_times_seconds) / 1_000_000
```

В расчёт времени включены DNS, установление соединения, TLS, редиректы, ожидание ответа и полное чтение конечного тела. Запуск и завершение рабочего процесса, паузы между запросами и вывод в консоль в знаменатель не входят. Измеряются байты HTTP-тела после удаления chunk framing, без декодирования Content-Encoding.

## Тесты

Тесты используют локальные HTTP/HTTPS-серверы и **не требуют интернета**. TLS проверяется с тестовым CA из `tests/fixtures`; ключ сервера предназначен только для этих тестов:

```bash
python3 -m unittest -v test_speed_test.py
```

Проверяются полные и пустые ответы с Content-Length, chunked и EOF, обрывы и повреждённый framing, редиректы, ошибки TLS/HTTP/DNS/соединения, оба таймаута, сохранение частичного результата, завершение worker и корректность формул. Проверки сигналов группы процессов и повреждённого IPC выполняются на POSIX; проверка отсутствия оставшихся CLI-процессов использует Linux `/proc`.

## Обработка ошибок и ограничения

- Код `0` означает, что все десять ответов прочитаны полностью. `Results` и итоговая скорость печатаются только в этом случае.
- При ошибке сети, HTTP, framing или таймауте серия останавливается с кодом `1`, при Ctrl+C — с кодом `130`. Ожидаемые ошибки выводятся без traceback.
- В `stderr` сохраняются число, байты и суммарное время завершённых запросов, отдельно — номер, известные байты, время и причина остановки текущей попытки. При принудительной остановке `at least N bytes` означает нижнюю границу: последний полученный progress; ещё не переданные счётчики и буферы ОС/TLS в неё не входят.
- Причины остановки: `http_error`, `network_error`, `io_timeout`, `download_timeout`, `incomplete_response`, `protocol_error`, `cancelled`, `worker_error`.
- Content-Length должен быть неотрицательным и согласованным во всех повторениях. Chunked требует полного framing, нулевого chunk и завершённых trailers. Повреждённые и неоднозначные длины отклоняются. Для ответа без длины и Transfer-Encoding EOF считается полным ответом; неизвестную недостачу обнаружить невозможно. 204 — успешный пустой ответ.
- Поддерживаются до десяти редиректов 301/302/303/307/308 только на HTTP(S). Промежуточные тела не скачиваются и не учитываются в объёме; время переходов учитывается. Повторных попыток при ошибке нет.
- Стандартная проверка HTTPS-сертификатов и proxy environment сохраняются.
- Каждую попытку выполняет отдельный процесс со `spawn`; следующая начинается только после его завершения и уборки. После отсечки остановка может занять ещё до 0,5 с на каждое из ожиданий terminate/join, kill/join и receiver join. Это не гарантия реального времени ОС. Неподтверждённая уборка даёт `worker_error` и прекращает серию.
- Недопустимый URL или таймаут отклоняется до начала работы (`argparse`, код `2`).
- Измерение отражает пропускную способность **до конкретного сервера по HTTP**, а не гарантированную максимальную скорость интернет-тарифа. На результат влияют сервер, сетевые задержки, TLS и размер файла.
